## 1. 학습 개요
- **학습 시기:** 2026년 9~10월
- **학습 상태:** 기초 개념 학습 및 발표 완료
- **실험 여부:** 직접 구현 및 실험은 진행하지 않음

연합학습의 기본 구조와 주요 기술을 이해하고, 기존 학습 방식과 비교했을 때 어떤 장점과 한계가 있는지 알아보기 위해 공부를 시작했다.

특히 원본 데이터를 직접 공유하지 않는 연합학습에서도 개인정보 보호 문제가 발생할 수 있다는 점에 집중했다. 
## 2. 연합학습의 기본 구조

연합학습은 여러 기관이나 클라이언트가 **원본 데이터를 중앙 서버에 직접 모으지 않고** 공동으로 모델을 학습하는 방식이다.

예를 들어 병원 A,B,C가 각각 환자 데이터를 가지고 있다면, 각 병원은 자체 데이터로 모델을 학습하고 모델 파라미터나 업데이트 정보를 중앙 서버에 전달한다.

중앙 서버는 전달받은 결과를 집계하여 글로벌 모델을 업데이트한다. 이 과정을 여러 라운드에 걸쳐 반복한다.

기존의 중앙집중식 학습과 달리 원본 데이터를 직접 모으지 않는다는 점이 특징이다.

### 학습하면서 이헤한 내용

처음에는 여러 기관이 함께 학습한다는 점에서 일반적인 분산학습과 비슷하다고 생각하였지만, 연합학습에서는 원본 데이터가 각 기관에서 벗어나지 않는다는 점이 중요하다는 것을 이해했다.

다만 연합학습이 일반적인 분산학습보다 개인정보를 보호하는 차원에서 앞서나간다 생각했지만 연합학습의 구조적인 측면에서 개인정보 보호를 완전히 보장한다는 의미는 아니라는 점도 알게 되었다.

## 3. 주요 학습 내용

### 3.1 FedAvg와 모델 집계

FedAvg는 클라이언트들이 학습한 모델 파라미터를 데이터 개수에 비례하여 가중평균하는 대표적인 집계 알고리즘이다.

일반적으로 클라이언트가 보유한 학습 데이터가 많을수록 글로벌 모델 업데이트에 더 큰 가중치가 부여된다.

- Aggregation은 여러 클라이언트의 학습 결과를 합쳐 글로벌 모델을 업데이트하는 과정이다.
- FedAvg는 각 클라이언트의 데이터 개수를 기준으로 가중치를 결정한다.

### 3.2 IID와 NON-IID

IID는 데이터가 동일한 확률분포를 따르며 한 데이터를 뽑은 결과가 다른 데이터를 뽑는 데 영향을 주지않는 것을 의미하고 NON-IID는 위와 반대 상황, 어떤 데이터가 얼마나 들어있는지가 다른 것이다

연합학습에서는 클라이언트마다 데이터 분포가 다른 NON-IID 환경이 중요한 문제로 다뤄진다.

예를 들어 어떤 병원에는 특정 질병을 가진 환자가 많고 다른 병원에는 해당 질병의 환자가 적을 수 있다.

이 경우 각 병원에서 학습한 모델의 특성이 달라지고, 글로벌 모델의 성능에도 영향을 줄 수 있다.

### 3.3 동형암호

동형암호는 암호화된 데이터를 복호화하지 않고도 연산을 수행할 수 있는 암호 기술이다. 

암호문 상태에서 계산한 결과를 복호화하면 대응하는 평문 연산 결과를 얻을 수 있다.

> [!IMPORTANT]
> 동형암호의 기본 원리는 이해했지만, 구체적인 암호화 방식과 수학적 계산 과정은 추가 학습이 필요하다.

### 3.4 안전한 다자간 계산과 보안 집계

안전한 다자간 계산은 참여자들이 각자의 비공개 입력을 공개하지 않으면서 공동으로 계산하는 기술이다.

연합학습에서는 개별 클라이언트의 모델 업데이트를 숨기면서 전체 집계 결과를 얻는 보안 집계에 활용할 수 있다.

가림값을 이용하는 방식에서는 각 클라이언트의 값에 가림값을 적용하고, 집계 과정에서 가림값이 상쇄되도록 설계한다.

- 가림값은 합계의 정확성을 유지하면서 개별 값을 숨기는 역할을 한다. 실제 안전하게 작동하려면 가림값을 비밀리에 준비하고, 참여자가 중간에 빠지는 상황 등도 처리해야한다. 
- 가림값이 적용된 값들이 계산되면서 상쇄되어 개별 값을 공개하지 않고도 전체 계산 결과를 얻을 수 있다는 기본 원리를 이해했다.

### 3.5 차등프라이버시

차등 프라이버시는 특정 개인의 데이터가 포함되었는지 여부에 따라 분석 결과가 크게 달라지지 않도록 통계적 보호를 제공하는 기술이다. 

쉽게 말하면 공개된 결과로 한 사람의 기록을 알아내기 어렵게 하는 것이다.

대표적으로 계산 과정이나 결과에 적절한 노이즈를 추가하는 방법이 사용된다.

- 노이즈를 아무렇게나 넣으면 차등 프라이버시가 되는 건 아니다. 한 사람의 기록이 결과를 얼마나 바꿀 수 있는지에 맞춰 노이즈의 크기를 수학적으로 정해야한다.

> [!IMPORTANT]
> 개인정보 보호 수준을 결정하는 수학적 원리와 노이즈가 모델 정확도에 미치는 영향은 아직 추가학습이 필요하다.

## 4. 연합학습에서의 보안 문제

### 4.1 원본 데이터를 공유하지 않아도 정보가 유출될 수 있다.

연합학습에서는 원본 데이터를 중앙 서버로 직접 전송하지 않는다.

그러나 클라이언트가 전달하는 모델 파라미터나 업데이트 정보에 원본 데이터의 특징이 일부 반영될 수 있다.

공유된 정보를 분석하면 원본 데이터에 관한 정보를 추론하거나 일부 복원할 가능성이 있다.

- 이 내용을 학습하면서 연합학습이 원본 데이터의 직접적인 공유를 줄이는 기술이지만 모든 개인정보 유출 위험을 제거하는 기술은 아니라는 점을 이해했다.

### 4.2 화이트박스 환경에서의 위험

화이트박스 환경은 모델의 내부 구조나 파라미터 등에 접근할 수 있는 환경을 의미한다

연합학습에서는 모델 파라미터를 직접 관찰할 수 있는 상황이 개인정보 보호 문제로 이어질 수 있다.

따라서 어떤 정보를 공유하고 누가 접근할 수 있는지 고려해야 한다.

### 4.3 보안 기술과 효율성의 관계 

연합학습에서 개인정보를 보호하기 위해 동형암호, 차등프라이버시, 안전한 다자간 계산 등을 적용할 수 있다.

그러나 이러한 기술은 추가적인 계산 비용이나 통신 비용을 발생시킬 수 있다.

따라서 개인정보 보호 수준과 학습 효율성 사이의 균형도 중요한 해결 과제하는 점을 알게 되었다.

## 5. 공부하면서 관심을 갖게 된 문제

연합학습에서는 원본 데이터를 직접 공유하지 않지만, 모델 업데이트 정보가 외부에 전달된다는 점에서 정보 유출 가능성이 남아 있다.
