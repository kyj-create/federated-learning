## 1. 학습 개요

- **학습 시기:** 2026년 10월
- **학습 방법:** 논문 분석, 알고리즘 이해, 실험 그래프 해석, 질의응답 및 PPT 발표
- **실험 여부:** 직접 구현 및 재현 실험은 진행하지 않음

첫 번째 연합학습 기술동향 보고서를 공부하면서 FedAvg가 클라이언트의 데이터 개수를 기준으로 집계 가중치를 결정한다는 점을 알게 되었다.

하지만 클라이언트마다 데이터 분포가 다른 NON-IID 환경에서는 데이터 개수가 실제 모델 성능 기여도를 충분히 나타내지 못할 수 있다는 문제가 있었다

## 2. 논문에서 해결하려는 문제

FedAvg는 클라이언트가 보유한 학습 데이터의 개수에 비례하여 모델을 가중평균한다.

그러나 데이터 개수가 같더라도 클라이언트마다 보유한 데이터의 종류와 분포는 다를 수 있다.

예를 들어 다음과 같은 상황을 생각할 수 있다.

-client 1: 숫자 0~9의 데이터 보유
-client 2: 숫자 0~9의 데이터 보유
-client 3: 숫자 7, 8, 9의 데이터에 편중

세 클라이언트의 데이터 개수가 같다면 FedAvg에서는 비슷한 가중치를 받을 수 있다.

하지만 Client3 의 데이터 분포는 client 1, client 2와 다르기 때문에 글로벌 모델에 미치는 영향도 다를 수 있다.

논문에서는 이러한 문제를 해결하기 위해 데이터 개수 대신 **글로벌 모델의 성능에 대한 클라이언트별 기여도**를 평가하는 방법으르 제안한다.

## 3. Shapley Value 기반 집계 알고리즘

### 3.1 Shapley Value

Shapley Value는 여러 참가자가 협력하여 만든 결과에서 각 참여자의 기여도를 평가하는 개념이다.

연합학습에서는 클라이언트들이 글로벌 모델 성능에 얼마나 기여했는지를 측정하는 데 활용할 수 있다.

핵심은 클라이언트가 가진 데이터 개수만 보는 것이 아니라, 해당 클라이언트가 참여 했을 때 모델 성능에 얼마나 기여하는지 평가하는 것이다.

### 3.2 논문에서 제안한 집계 과정

1. 클라이언트의 부분집합을 구성한다.
2. 각 조합에서 글로벌 모델의 성능을 평가한다.
3. Shapley Value를 계산하여 클라이언트별 기여도를 측정한다.
4. Softmax를 이용하여 기여도를 집계 가중치로 변환한다.
5. 기여도 기반으로 모델을 집계한다.
6. 글로벌 모델을 업데이트한다.

### 3.3 Softmax의 역할

Shapley Value로 계산한 기여도를 실제 모델 집계에 사용할 가중치로 변환하기 위해 Softmax를 활용한다.

이를 통해 기여도가 높은 클라이언트의 모델이 글로벌 모델에 더 크게 반영되도록 한다.

> [!IMPORTANT]
> 기여도를 가중치로 변환하는 과정은 아직 학습하지 않았다.

## 4. 논문의 실험 결과 이해

아래 결과는 논문에서 제시한 실험을 발표 자료로 분석한 내용이며, 직접 수행한 실험 결과가 아니다.

### 4.1 IID 환경

발표 자료에 정리한 실험 결과에서는 FedAvg와 제안 방법의 정확도가 모두 98.18% 이다.

IID 환경에서는 두 방식이 유사한 성능을 보인다는 점을 확인했다.

### 4.2 NON-IID 환경

발표 자료에 정리한 실험 결과는 다음과 같다.

| 방법 | 정확도 |
|---|---:|
| FedAvg | 96.62% |
| Shapley Value 기반 집계 | 98.13% |

제안 방법의 정확도가 약 1.51%p 높았다.

이를 통해 해당 실험 조건에서는 클라이언트의 성능 기여도를 반영하는 방식이 NON-IID 환경에서 글로벌 모델 성능을 개선할 수 있다는 점을 이해했다.

### 4.3 학습 라운드별 정확도 변화

논문의 그래프를 분석하면서 NON-IID 환경에서는 약 30라운드 까지 제안 방법의 정확도가 높게 나타난다는 점을 확인했다.

초반부에서 정확도의 차이가 나지만 라운드가 반복될 수록 차이가 줄어들어 논문이 제시한 방법이 꼭 필요할까? 라는 의문점이 들었다.

### 4.4 클라이언트별 기여도 변화

NON-IID 환경에서 숫자 7, 8, 9에 편중된 데이터를 가진 Client 3의 기여도가 다른 클라이언트보다 낮게 나타났다.

Shapley Value로 측정한 기여도를 Softmax를 통해 가중치로 변환했을 때 Client 3의 가중치가 0에 가까워지는 결과를 확인했다.

이 결과를 통해 데이터 분포가 다른 클라이언트를 기여도 평가 과정에서 구별할 수 있다는 점을 이해했다.

단, 이러한 결과가 모든 NON-IID 환경에서 동일하게 나타난다는 의미는 아니다.

## 5. 학습하면서 이해한 내용

### 5.1 FedAvg와 기여도 기반 집계의 차이

처음에는 클라이언트가 보유한 데이터 개수가 집계 가중치를 결정한다는 점을 중심으로 FedAvg를 이해했다.

하지만 논문을 공부하면서 데이터 개수가 같더라도 글로벌 모델 성능에 미치는 기여도는 다를 수 있다는 점을 알게 되었다. 

FedAvg는 데이터 개수를 기준으로 가중치를 결정하는 반면, 논문에서 제안한 방식은 글로벌 모델 성능에 대한 기여도를 측정하여 가중치에 반영한다.

### 5.2 Shapley Value의 계산 비용

논문에서 제안한 방식에도 한계가 존재한다.

Shapley value는 클라이언트의 여러 조합을 고려하여 기여도를 계산하기 때문에 클라이언트 수가 증가하면 계산량이 크게 증가할 수 있다.

발표를 준비하면서 클라이언트 수가 증가할수록 가능한 부분집합의 수가 지수적으로 증가한다는 점을 확인했다.

따라서 성능 개선뿐 아니라 실제 연합학습 환경에서의 계산 효율성도 고려해야 한다.

## 6. 논문을 공부하면서 생긴 보안 관련 질문

기여도 기반 집계 알고리즘을 공부한 후, 기여도를 평가하는 과정 자체가 새로운 보안 문제와 연결될 수 있지 않을까 생각했다. 

### 6.1 기여도 정보가 데이터 특징을 드러낼 수 있을까?

연합학습에서 클라이언트별 기여도와 라운드별 변화를 관찰할 수 있다면, 이를 통해 해당 클라이언트가 가진 데이터의 특징을 추론할 가능성이 있는지 궁금해졌다.

예를 들어 어떤 병원이 글로벌 모델 학습에 참여한 후 특정 질병의 예측 정확도가 높아졌다면, 해당 병원이 그 질병과 관련된 데이터를 많이 보유하고 있다고 추측할 수 있지 않을까 생각했다.

> [!NOTE]
> 질병별 예측 성능 정보가 함께 공개된다면 추론 가능성이 높아질까?
> 클라이언트별 기여도만으로 기관의 데이터 분포를 추론할 수 있을까?
> 공격자가 실제로 어떤 정보에 접근할 수 있어야 이런 추론이 가능할까?
> 기관이 보유한 특정 질병 데이터의 특징이 알려지는 것이 어떤 보안 문제로 이어질 수 있을까?

현재는 연구 질문을 제기한 단계이며, 실제 공격 가능성을 실험으로 검증하지 않았다.

### 6.2 높은 기여도를 유지하면서 모델을 공격할 수 있을까?

기여도가 높은 클라이언트의 업데이트가 글로벌 모델에 더 크게 반영된다면, 악의적인 클라이언트가 기여도 평가를 악용할 가능성도 생각해 보았다.

예를 들어 일반적인 데이터에서는 좋은 정확도를 유지하지만, 특정 표시가 있는 숫자 1만 숫자 7로 잘못 분류하도록 모델을 조작하는 상황이다.

이러한 공격이 전체 정확도에 큰 영향을 주지 않는다면 기여도 평가 과정에서 발견되지 않을 가능성이 있을지 궁금해졌다.

> [!NOTE]
> 악의적인 클라이언트가 높은 기여도를 유지하면서 백도어 공격을 수행할 수 있을 까?
> 전체 정확도만으로 이러한 공격을 발견할 수 있을까?
> 기여도 기반 집계에서 공격을 탐지하려면 어떤 평가 지표가 추가로 필요할까?

> [!IMPORTANT]
> 백도어 공격에 대한 원리를 학습해야 위의 질문들에 답을 할 수 있을 것 같다.

### 7.1 7.1 Exploiting Unintended Feature Leakage in Collaborative Learning

- Authors: Melis et al.
- Year: 2019

공동 학습 과정에서 공유되는 모델 업데이트를 통해 다른 참여자의 비공개 데이터 특징을 추론할 수 있다는 문제를 다룬 연구이다.

다만 모델 업데이트를 이용한 추론과 기여도 정보만을 이용한 추론은 서로 다른 문제 이므로 별도의 검증이 필요하다.
