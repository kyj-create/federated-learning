## 2. Research Background

연합학습에서는 여러 클라이언트가 각자의 데이터로 모델을 학습한 뒤, 서버가 학습 결과를 모아 글로벌 모델을 만든다. 클라이언트마다 보유한 데이터의 종류와 분포가 다를 수 있다.

## 3. Research Problem

FedAvg는 일반적으로 클라이언트의 데이터 수를 기준으로 집계 가중치를 정한다. 하지만 데이터 수가 같아도 글로벌 모델 성능에 도움이 되는 정도는 다를 수 있다. 이 논문은 각 클라이언트의 성능 기여도를 집계에 반영하는 문제를 다룬다.

## 4. Proposed Method

논문은 클라이언트 조합별 모델 성능을 평가하고, Shapley Value로 각 클라이언트의 기여도를 계산한다. 계산한 기여도를 Softmax로 집계 가중치로 바꾼 뒤 글로벌 모델을 갱신한다.

## 5. Experimental Setup and Results

발표 자료에서 정리한 **논문 저자의 결과**는 다음과 같다. 내가 직접 재현한 실험 결과는 아니다.

| 데이터 조건 | FedAvg | 제안 방법 |
|---|---:|---:|
| IID | 98.18% | 98.18% |
| Non-IID | 96.62% | 98.13% |

IID: 두 방식이 같은 성능을 보이며 데이터 분포가 정상적인 상황에서 기존 FedAvg 알고리즘 만큼의 성능을 보이는 것을 확인할 수 있었다.
NON-IID: 데이터 분포가 고르지 않은 상황에서 제안 방법의 성능이 약 1.5%p 높은 것으로 나타났다.

## 6. Key Technical Concepts

- **FedAvg:** 클라이언트가 학습한 모델을 서버에서 집계하는 대표적인 방법
- **Non-IID:** 클라이언트마다 데이터 분포가 서로 다른 상황
- **Shapley Value:** 여러 참여 조합에서 각 클라이언트가 성능에 더한 기여를 평가하는 방법
- **Softmax:** 기여도 점수를 집계에 사용할 가중치로 변환하는 함수

## 7. Security Perspective

성능 기여도를 집계에 사용하는 방법이 보안 측면에서는 어떤 영향을 줄지 궁금해졌다. 기여도 정보가 공개된다면 기관의 데이터 특징을 추론하는 단서가 될 수 있는지, 악의적인 업데이트도 높은 기여도를 받을 수 있는지 살펴보고 싶다. 이 질문은 논문에서 입증한 성능 개선과는 별개다.

## 8. My Understanding

데이터 수만으로 모든 클라이언트의 기여를 판단하기 어렵다는 점을 이해했다. 논문이 제안한 방법은 글로벌 모델의 성능에 대한 기여를 평가해 집계 가중치를 정한다. 다만 기여도가 높다는 사실만으로 해당 클라이언트가 안전하다고 판단할 수는 없다.

## 9. Remaining Questions

- 기관별 기여도와 라운드별 변화가 공개되면, 다른 참여자가 기관의 데이터 특징을 추론하는 데 도움이 될까?
